# Private observer epoch integration

Product private observation now calls `/api/v1/rooms/:id` and its messages/wait resources with the existing capability Authorization boundary. GET never joins a participant. First reading omits after; later reads use only the last DOM-applied epoch:sequence. Limit and timeout are omitted so the actual room policy supplies its current bounds. Pagination and waits respect the existing two-second minimum; 429 honors Retry-After through the single existing retry path. Pause/navigation/pagehide abort the current read and discard responses which no longer own the screen.

Explicit history_gap/history_reset clears the old message/sender window, keeps a visible fixed service notice and starts the server's bounded replacement window. An unexplained epoch change or invalid cursor cannot silently reset to zero. Same-epoch duplicates are skipped. Closed history still drains has_more pages before stopping. The feed exposes data-applied-cursor and individual message data-cursor for non-secret validation. Tabs, append and replacement preserve the page position and the prior reader/follow relation.

Private notice uses actual immutable metadata: memory/persisted mode, retention seconds, notice version, metadata persistence, link-possession access and no E2EE. It distinguishes agent machine acknowledgement from human consent and imports the generated service safety component. No speculative duration, policy size, fake observer counts or client role privilege is supplied. Shared product/QA room renderer, required memory/persisted/gap/reset/pause/rate-limit states and graph edges were updated together. Public engine files and backend contracts were not edited.
