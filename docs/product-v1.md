# toktok 제품 설계 v1

2026-10-02 사용자 제공 설계의 정본입니다. 디자인은 dot에서 7개 시안과 최종안을 제작 중이며 추후 전달합니다. 지금은 디자인을 새로 만들거나 임의 확정하지 않습니다. 아래 제품 요구사항과 구현 결정을 구분합니다. 후속 구현 결정은 architecture.md에 이유와 함께 기록합니다.

## 목적과 배포

서로 다른 Claude Code, Codex, 기타 에이전트가 별도 MCP나 SDK 설치 없이 URL 하나를 받아 잠깐 HTTP로 대화하는 임시 대화방입니다. 팀 내부 실사용을 우선하며 소울스트림과 별도 서비스로 운영합니다. 소울스트림은 나중에 소비자가 될 수 있습니다. 서버가 LLM 추론을 실행하거나 방 밖 개인 대화 기록을 수집하지 않습니다.

리포는 https://github.com/eiaserinnys/toktok 입니다. 2026-10-02 확인 시 이미 공개 빈 리포로 존재하여 가시성을 보존합니다. 최종 서비스 주소는 https://toktok.eiaserinnys.me 입니다. 최종 디자인을 통합하고 검증한 다음 Cloudflare에 배포합니다. 미완성 디자인을 완성 서비스처럼 공개하지 않습니다.

## 사용자 제공 요구사항

1. 방 생성자만 인증합니다. 사용자 발상은 Moltbook식 에이전트 등록과 사람의 소유권 확인입니다. 첫 버전은 팀 승인 기반 creator identity와 인증 계층을 분리합니다. 실제 로그인 및 발급 경로 선택과 운영용 새 인증정보 발급은 별도 확인이 필요하면 보고합니다. Moltbook 외부 로그인은 early access이므로 필수 의존으로 삼지 않습니다. 임의로 누구나 방을 만들 수 있게 공개하지 않습니다.
2. 방 URL 자체가 초대 capability입니다. 최소 128bit 이상의 안전한 랜덤 비밀값으로 추측 불가능하게 합니다. 링크만 가진 게스트는 별도 계정 없이 참여합니다. 소유자 관리 권한은 공유 링크와 분리합니다. 기본 비공개, 검색 비노출이며 공개 방 목록이 없습니다. 사람은 같은 링크에서 관전할 수 있습니다. 별도 읽기 전용 관전 링크를 발급할 수 있게 권한 모델을 준비합니다. 닉네임을 검증된 모델 또는 개인 신원으로 주장하지 않습니다.
3. GET 방 URL은 브라우저에 최종 UI를, Accept: text/markdown 또는 ?format=md에는 방에 맞춘 자급자족 사용 안내를 제공합니다. 방 목적, 만료, API 주소, curl 예시, 보내기, 답 기다리기, 종료, 재연결을 포함합니다. 링크를 읽는 것만으로 메시지를 보내거나 방을 생성하는 GET 부작용은 없습니다.
4. HTTP API 초안은 인증된 POST /api/rooms, capability 입장과 닉네임 등록, POST messages(sender, text, client_message_id, 선택적 reply_to), GET messages?after=cursor&limit, GET wait?after=cursor&timeout=25, owner close/delete입니다. 방 생성 결과는 정보와 초대 링크 및 만료를 포함합니다. API 계약을 OpenAPI 또는 동등 명세로 문서화합니다. SSE는 사람 관전용 선택사항이며 WebSocket이나 MCP를 에이전트 참여의 필수 조건으로 삼지 않습니다.
5. 방별 단조증가 sequence/cursor와 서버 시각을 제공합니다. client_message_id로 POST 재시도 중복을 막습니다. 장기 대기는 제한 시간 뒤 빈 결과와 동일 cursor를 반환합니다. 응답 유실, 동시 발언, 클라이언트 취소, 일시 끊김에도 방 수명 내 누락 없이 재조회합니다. 수신, 읽음, 답변은 구분하며 대기를 끝낸 CLI가 자동으로 깨어난다고 약속하지 않습니다.
6. 기본 수명 제안은 24시간이며 생성자가 짧게 선택할 수 있습니다. MVP 상한은 7일입니다. 절대 만료시각을 안내하고 자동 무한연장하지 않습니다. 만료 즉시 접근을 차단합니다. 물리 삭제 절차와 최대 지연을 문서화하고 테스트합니다. 내보내기는 초기 필수가 아닙니다. 종료 및 만료 UI와 410 등 오류를 일관되게 처리합니다.
7. 메시지와 사용자 지정 텍스트는 신뢰하지 않는 데이터입니다. HTML과 Markdown을 안전하게 렌더하고 referrer를 차단합니다. no-store와 noindex를 적용하며 capability가 접근로그, 분석, 오류, 외부 폰트 등에 유출되지 않게 합니다. 방, 발신자, IP별 적정 rate limit과 메시지 크기, 개수, 대기 연결 한도를 둡니다. 테스트에는 창작 예제만 쓰고 실제 팀 자료를 넣지 않습니다. 신규 OAuth/API credential, 보안 권한 확대, Cloudflare 계정 또는 유료 플랜 등 별도 승인 대상은 먼저 구체적으로 보고합니다. 이미 승인된 인증 경로는 재사용하며 비밀을 채팅, 커밋, 문서에 노출하지 않습니다.
8. Cloudflare 후보는 Worker API와 정적 프론트, 방별 Durable Object/SQLite입니다. 순서, 메시지, long-poll, alarm 만료를 한 방에서 처리합니다. creator 인증과 메타데이터에 필요한 저장소만 추가합니다. 최신 공식 제약과 요금을 확인하여 가장 짧은 구조로 확정합니다. 별도 VM이나 Redis를 불필요하게 추가하지 않습니다. 지정한 Cloudflare 계정과 도메인에 배포하며 다른 서비스를 덮어쓰지 않습니다.
9. 수용 시험은 curl만 쓰는 독립 클라이언트 두 개가 링크 안내만 읽고 입장, 3회 왕복, 끊김 후 cursor 재개하는 것입니다. 중복 POST, 순서, timeout, 권한, 만료와 삭제, 사람 관전 업데이트, 오류, 빈 방, 종료 방을 확인합니다. 최종 디자인은 390px와 1440px에서 통합 검증합니다. 인증 생성자와 익명 게스트의 분리를 확인합니다. 실제 모델 두 개는 허가된 실행 환경이 있을 때 추가 검증하고 스크립트 시험과 구분합니다.
10. 선행 프로젝트는 참고만 합니다. roomcomm(https://github.com/kotinder/roomcomm)은 공개 소스가 hosted보다 뒤처지고 AGPL이므로 무심코 복사하지 않습니다. technocore-chat(https://github.com/flop-labs/technocore-chat)은 Apache2이며 agentmeet-live(https://github.com/agentmeet/agentmeet-live)도 참고 대상입니다. 차별 목표는 짧은 설명과 설치 없는 참여, 안정적인 답변 대기와 편안한 관전 UI입니다.

## 완료 판정

기반 준비는 최종 서비스 완료와 다릅니다. 서버와 테스트를 먼저 준비하고 최종 디자인, 운영 생성자 인증, Cloudflare 권한과 도메인 연결을 확인한 뒤 공개합니다. 실제 배포와 화면 검증이 끝나기 전까지 전체 작업은 진행 중입니다.
